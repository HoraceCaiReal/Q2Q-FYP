## 当前架构

当前系统架构以 [最终架构](05-最终架构.md) 为准（2026-10-19 晚**概念更正**）：

- **orchestration** 是整个架构的调度者：接子目标、收状态、路由（watchdog）、判完成（checkpoint）、触发重规划、记账。
- **harness** 只是 **Q2Q-VLM 这个节点的外壳**：把状态预处理成 token → 喂给 Q2Q-VLM → 把输出取回成 `CaseParams`；它**不是**调度大框。
- **Km-Transformer 属于 Q2Q-VLM**，不是与硬编码并列的另一条策略。

数据流：LLM/WM 输出 Subgoal → orchestration（不危险→harness，危险→EmbeddedRollout 硬编码）→ 符号后端 → Executor → ROS2/Gazebo。
执行结果经 EpisodeRecorder 全量落盘 → replay 机器筛选 → 人工/LLM 复盘，两者都作为 feedback 喂回 LLM。ROS2（rclpy）贯穿整个架构。

| 层 | 当前职责 |
|---|---|
| 上层规划 | 输出结构化 Subgoal（case / prompt / constraints） |
| Orchestration（总调度） | 子目标推进 + watchdog（危险判定 / NN-硬编码路由 / 是否需要重规划）+ checkpoint（完成判定）+ dataflow（状态收集） |
| Harness（VLM 外壳） | `WorldState + Subgoal → token` → 调 Q2Q-VLM → 输出 `CaseParams` |
| Q2Q-VLM | 视觉-语言-动作模型（含 Km-Transformer：定性选 case + 定量出 params） |
| 硬编码兜底 | EmbeddedRollout（安全兜底 / benchmark 基线 / 数据自举） |
| 符号后端 | OSQP（机械臂）/ A*、Hybrid A*（导航） |
| 数据与评测 | EpisodeRecorder（全量成功/失败 + **硬编码触发**）→ replay（机器筛选）→ 人工/LLM 复盘（feedback → LLM） |
| 通信与执行 | ROS2；当前Jackal J100 + Kinova Gen3 Lite + 2F Lite，Humble/Fortress；旧Husky命名空间保留 |

Orchestration 包含两条同等重要的链路：

- 执行：状态获取 → Subgoal → watchdog 路由 / checkpoint 判定 → 不危险走 harness→Q2Q-VLM，危险走 EmbeddedRollout → 求解 → 执行监控 → 完成或恢复。
- 数据与评测：EpisodeRecorder 全量落盘 → replay 机器筛选 → 人工/LLM 复盘 → feedback 回 LLM；回放、批量评测、回归测试与后续训练。

**硬编码触发也入日志**：watchdog 切到 `EmbeddedRollout` 时，事件写入 EpisodeRecorder（`kind: hardcoded_triggered`），replay 单独统计；**理想情况不应触发**（兜底，不替代神经网络）。

state monitor 和 pipeline 是核心职责。模型反射模式与 orchestration 的停止、取消、超时和恢复职责需要明确接口边界，不能仅凭模型设计就视作完成执行保护。以上是待实现架构，不表示闭环或安全性已经验收。
