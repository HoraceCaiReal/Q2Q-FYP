# 移动机械臂与仓库仿真选型

调研日期：2026-10-15。状态：用户已同意本套配置，作为项目实施选型；尚未下载、安装、编译或实测候选平台。这里的插件指 ROS2、导航、操作与仿真组件。选型依据是官方文档与源码，运行可行性须通过后续验收。

## 结论

首选验证组合：Ubuntu 22.04 + ROS2 Humble + Gazebo Fortress + Clearpath Husky A200 + Kinova Gen3 Lite + Kinova 2F Lite 夹爪。
采用 Nav2、MoveIt2、ros2_control 作为执行基础；自主编写 Harness、ROS2 适配接口、状态监控、任务调度、恢复与评测 pipeline。
仓库选择自主搭建轻量 SDF 测试场景，参考 Clearpath warehouse 的组织方式。完整大仓库和复杂视觉资产推迟。

选择理由：Clearpath 的 Humble 官方教程明确演示 A200 + Gen3 Lite 的控制器与 MoveIt 集成，配套模拟器使用 Fortress，有 Nav2 配置和仓库地图参考。比自己拼接底盘和 UR3 更少一个集成层。此结论不等于已证实夹爪接触抓取稳定或当前虚拟机能流畅运行。

## 候选比较

| 候选 | 核实到的证据 | 本项目取舍 |
|---|---|---|
| Husky A200 + Kinova Gen3 Lite | 官方 Humble 移动操作示例，明确机器人配置、夹爪、控制器和 MoveIt 启动方式 [1] | 首选验证；底盘并非专门的室内仓储机型，但足以承载系统架构实验。需验证转弯误差、可达范围和物体抓取 |
| TIAGo 单臂 | 官方 humble-devel 仿真仓库同时提供 Nav2、SLAM、MoveIt 启动 [2]；当前 launch 含 gazebo_version 切换，package.xml 同时列出 gazebo_ros 与 gz_ros2_control [14] | 有竞争力的备选；不能称其仅支持 Classic。需进一步锁定新 Gazebo 路线与各依赖版本。旧教程中的 Classic 已 EOL [3]；不能直接照旧教程安装 |
| Robotnik RB-KAIROS | 当前仓库列出移动操作机型；但所查看 humble-devel 仿真 README 安装段指向 Jazzy/Harmonic，RB-KAIROS 标为 Limited [4] | 版本文档与分支名不能视为一致，暂不承担验证/迁移成本 |
| Husky + UR5e / 自行给 UR3 加底盘 | Clearpath 配置文档支持 UR 系列描述 [5]，darshmenon 提供固定臂抓放参考 | 可作后续扩展；本轮没有取得与 A200+Gen3 Lite 同等明确的当前 Humble 完整组合示例，不作为近期首选 |

不按星数或宣传视频选择；优先看明确的 ROS/仿真器版本、完整机器人组合、控制器和上层接口。

## 软件组件选择

| 层 | 首选 | 为什么及边界 |
|---|---|---|
| 仿真 | Gazebo Fortress + clearpath_simulator | 遵循 Clearpath Humble 官方配套，不混入 darshmenon 的 Harmonic 插件 [6] |
| 模型装配 | Clearpath robot.yaml + 官方 URDF/Xacro | 复用底盘、机械臂、夹爪模型；自己配置安装关系与传感器 |
| ROS 与仿真桥接 | 官方 Clearpath 生成的 ROS/Gazebo bridge 与仿真控制配置 | 具体包名和插件版本以 Humble 依赖为准，不照抄 Jazzy/Harmonic 的配置 |
| 底层控制 | ros2_control 与机器人配套控制器 | 使用配套底盘控制器、机械臂轨迹控制器及夹爪接口；不重复加载另一套底盘驱动插件 [7] |
| 导航 | Nav2；初始候选 NavFn + DWB | 先检查 Clearpath 实际配置，若不同则先复现官方配置；NavFn 可作为传统路径规划基线，DWB 用于局部执行 [8] |
| 定位 | map_server + AMCL | 使用与场景一致的地图；先固定环境，SLAM Toolbox 留作建图工具，不要求每次演示在线建图 |
| 机械臂规划 | MoveIt2 + OMPL，候选 RRTConnect | 利用官方 MoveIt 配置；抓放阶段由 orchestration 编排。MTC 暂不作为必需依赖 [9] |
| 坐标与状态 | tf2、robot_state_publisher、joint_states、odometry、/clock | 按时间戳和坐标系组织状态；不要把仿真真值、估计值和传感量混为一谈 |
| 数据记录 | rosbag2 + 自研 JSONL 事件日志、CSV 指标 | bag 保存选定原始话题，事件日志保存 task/step ID、case、params、命令、反馈及故障；实际 schema 后续制定 |
| 观察工具 | RViz2、ROS2 CLI，按需 rqt_graph | 先满足查看坐标、路径、状态和任务结果，不先做 Web dashboard |
| 调度核心 | 自研 Python/rclpy 状态机与异步 Action 适配（orchestration） | 自己实现调度、monitor、有限恢复与数据关联；**harness 只是 Q2Q-VLM 的外壳**，不承担调度；不接管 Nav2 内部所有导航逻辑 |

Nav2 的内部行为树负责导航子任务；orchestration 负责订单与跨导航/操作阶段调度。需要限定各层重试预算，防止两层同时重试。
模型策略先以可替换接口保留。OSQP、自研 A*、VLM、LLM/WM、LoRA 和 RL 不属于近期基础平台必需安装项；未来通过适配器接入。

## 仓库选择与初始设计

三个可选来源：

1. Clearpath warehouse：与首选模拟器一致，官方 Nav2 示例带有配套地图 [10]。实际 SDF 引用了多个 Fuel 远程模型，不能假定文件很小就意味着资源少或可以离线直接运行 [11]。
2. AWS RoboMaker Small Warehouse：可用于布局和资产参考，但仓库已归档，默认分支为归档说明，旧代码位于原分支；不作为当前维护的依赖基座 [12]。
3. 自建轻量 SDF：最适合当前交付。用基本几何体描述地面、墙、货架、操作台、料箱与商品，按需加入少量经许可核对的外部素材。

选择第 3 项，以第 1 项的 world/地图组织方式为参考。初始建议：

- 约 8 m × 10 m 的小场地，两个拣选工位，一个订单完成区；尺寸为草案。
- 每工位一个源料箱和一个目标料箱；初始 2–3 个规则物体，后续增加堆叠、遮挡和随机位置。
- 先导航到工位、停车确认、展开机械臂、抓放、收臂，再移动到下一工位；不要求底盘与机械臂同时运动。
- 台面高度、料箱深度、停靠位和通道宽度须根据所选模型碰撞体与实际可达空间验证，不能先凭外观固定。
- 地图与障碍配置必须对应，场景版本及随机种子进入实验记录。
- 第一期物体位姿可由预设场景提供，并显式标注为真值基线；不能把它记成视觉感知成果。
- 物理抓取必须验证物体随夹爪抬升且放置成功。若使用附着简化，明确标记为简化执行，不将其报告为接触抓取能力。

此场景能测试订单调度、导航/操作互锁、执行失败和数据闭环；初期规则物体实验不是完整杂乱料箱抓取评测。

## 资源与准入验证

当前虚拟机只有 4 GB 内存，宿主约 16 GB。官方推荐独立 GPU 获得更好仿真性能 [6]；VirtualBox 的 128 MB 显存和 3D 开关不能证明负载满足。初步工程建议是在宿主余量允许时分配 6–8 GB 内存，实际决定前先检查宿主占用；本轮未改配置。

初始仅启用一个 2D 激光雷达；RGB-D 在需要视觉数据时再开启，限制分辨率与频率。先单机器人、少量动态物体、无阴影；按需选择 GUI 或 RViz，避免同时加载复杂显示。headless 不等于传感器渲染不再需要图形支持。

正式采用前，最多两个下午验证以下条件：

1. 明确固定 ROS/Gazebo/机器人包版本和可获取依赖，遵循相应许可；不运行整套未知安装脚本。
2. 空场景生成完整机器人，TF、关节状态、里程计、激光、时钟正常；记录内存、CPU、仿真实时因子。
3. 底盘能导航到两个目标点，能取消并确认停止；停靠误差满足随后机械臂任务需要。
4. 机械臂能完成规划与执行，夹爪能开闭；取消语义、控制器终态和自碰撞检查可观测。
5. 在简单台面完成一次实际抓起/放下，单独报告接触稳定性。
6. Nav2 与 MoveIt 同时在线且互不抢控制；Harness 能串行调用并记录结果。

这些是未来验证门槛，本轮均未实测。若资源不满足，优先简化场景/传感器和调整运行环境；更换机器人前保留相同 Harness 接口，避免重写调度。
