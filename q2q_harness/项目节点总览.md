## 1. 概念与源码

- orchestration是总调度；Harness仅为Q2Q-VLM的外壳；Km-Transformer在VLM内部。[最终架构](../archive/开发基线/05-最终架构.md)。
- Windows `E:\毕设\q2q_harness`为唯一真源；VM `~/ros2_ws/src`是镜像，`~/.q2q/setup/a200_kinova`是生成物。
- Jackal J100 + Gen3 Lite + 2F Lite；沿用a200_0000命名空间不意味着底盘仍是Husky。

## 3. 状态、字段与验收

当前正常链：`IDLE → NAV_TO_PICK → WAIT_STILL → DOCKING → PICK_READY → PICKING → PICKED → STOWING → UNDOCKING → NAV_TO_PLACE → PLACE_READY → DONE`，另有CANCELING、FAILED。

- TaskCommand、TaskState、Grasp消息结构在第四轮未改变；UNDOCKING是现有字符串state字段的新值。
- TaskState.base_command_locked由节点覆盖为实际锁状态；**arm_executing和holding_object仍为false占位**，不表示已经测得“没有执行/没有持物”。
- 节点采用steady timer；消息header仍为仿真时间。不得用仿真钟衡量失联墙钟预算。
- 抓取数据失联窗口最终为10s；先取消和确认停止后才解锁，未确认需保锁。异常分支尚需现场故障注入。
- 高层当前为topic命令；Grasp反馈适配器主要发布start，不能把action定义中的阶段注释当成完整实时phase遥测。

两轮独立完整通过：200714和201108，落点误差32.73/23.36mm、late_events=0、最终锁释放，真实落地点连续3样本稳定。**这是运动学近似演示；物理抓取P7仍不成立。** 最后失败分支收紧后执行了离线测试和PICKING记录回放，不冒充又做了两次全链现场故障试验。

当前独立单任务会Stop/Start回基线；投放后未实现自动撤退、再次收臂和连续订单复位，不能直接宣称多订单循环已通。

## 5. 不要继承的旧结论

“top/mid/low/record全空”“Husky为当前底盘”“后半段从未实跑”“近似模式可以忽略夹爪失败”“P7已经物理通过”“每五次起栈必须重启VM/清SHM”均不能作为当前事实。

URDF摩擦/阻尼转换通路已核实；DetachableJoint未验收，不应称在本机已证明不可用。合成相机不是实时物体真值；当前抓取/落点以Gazebo pose/info验收。
