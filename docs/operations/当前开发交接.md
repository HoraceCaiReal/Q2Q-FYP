```powershell
# 改过源码才部署；五个sim包加mid/low/record，共8个ROS包
.\.dsh\step3.ps1 -Action Deploy
# 明确选择20ms近似搬运配置；原50mm物理对照文件仍为5ms
.\.dsh\step3.ps1 -Action Start -World q2q_warehouse_grasp50 -KinematicCarry
# VM后台运行一轮，LAUNCHED不等于PASS
.\.dsh\step7.ps1
# 演示/答辩：一条命令搞定（起栈 + 挂 Gazebo 窗口 + RViz + 跑链 + 自动截关键帧）

.\.dsh\step3.ps1 -Action Status
# 完成后按本轮标记停止
.\.dsh\step3.ps1 -Action Stop
```

长任务在VM后台运行，SSH断线不带走试验。`step7_trial.py`用flock拒绝重复试验，每episode独立日志。`run/step7_console_时间.log`为入口输出，`run/step7_日期时间/`保存五节点日志、scene.log和总结JSON，`~/.q2q/records/episode/task_state.jsonl`保存转移链。`passed=true`还必须包含独立物体落点验收；只有DONE不算。

当前支撑插件仅50mm世界加载。20ms配置由Start生成到世界快照，控制状态JSON记录kinematic_carry及SHA256；默认世界、5ms对照和80mm世界不能混成同一验收条件。不要使用-GripperMode suction：那是早期DetachableJoint实验，与当前运动学支撑不同。

## 仍需保持的边界

- 运动学支撑不是机器人抓取力学成果，真实吸附、摩擦夹持可靠性尚未解决。
- 当前为已知场景、真值定位及静止操作阶段的场景刷新；连续移动操作、真实感知、载物完整碰撞/受力模型尚未验收。
- 已验证的取消范围和未覆盖分支以修复报告为准，不能把离线事件表当全阶段实测。
- 不广泛pkill、不清空/dev/shm；bring_up3.sh已改为一次启动并有界检查，不做三轮盲重启。未经具体诊断，不把“重启VM”写成固定维修步骤。
- 独立pose_move.py旧CLI的直接执行/返回码问题仍不属于当前安全抓取路径；不要误用。

概念仍为orchestration总调度、Harness仅Q2Q-VLM外壳、Km-Transformer在VLM内；本轮串行协调器不等于完整VLM+Harness架构。[节点总览](../../q2q_harness/项目节点总览.md)、[最终架构](../../archive/开发基线/05-最终架构.md)。
