# 第 3 步导航运行

当前基线是 **Gazebo 物理真值定位 + 明确由 SDF 生成的地图 + 理想二维激光 + NavFn + Regulated Pure Pursuit**。这是《基本目标》第 3 步允许的仿真真值路线。AMCL 保留入口，尚未作为本基线验收；原生 GPU 激光、视觉感知和抓取不属于本次导航通过范围。

## Windows 入口

开工先读 [当前开发交接](当前开发交接.md)，先 Status；已运行时不要重复 Start。故障诊断前读 [复盘](../evaluations/2026-10-22-故障复盘与防复发.md)，不按旧日志重设环境。

在 `E:\毕设` 的 PowerShell 中运行。Ubuntu VM 需已开机，NAT SSH 为 `ros@127.0.0.1:2222`。

```powershell
pwsh -File .dsh\step3.ps1 -Action Deploy
pwsh -File .dsh\step3.ps1 -Action Start
pwsh -File .dsh\step3.ps1 -Action Test
pwsh -File .dsh\step3.ps1 -Action Status
pwsh -File .dsh\step3.ps1 -Action Stop
```

Deploy 同步两个 ROS 包并构建。Start 启动后台仿真，单独成功不代表验收通过。Test 会等导航 active、新鲜 TF 和物理里程计，再依次测试目标 A、目标 B、取消；遇失败就停止，不继续污染后续动作。只有 `STEP3_PASS=True` 才是动作测试通过。

每次启动生成独立的 `~/.q2q/runs/step3_<时间>/`，测试在其中的 `test_<时间>/` 保存日志、三个 JSON 与 summary.json。`~/.q2q/runs/step3_control.json` 指向当前运行。Stop 按运行标记追踪本次所有子进程，父进程退出不能当成清场完成；Start 会拒绝残留的同名 Gazebo。

Status 的 running 主要检查父进程，不是完整健康检查；若 false 但仍有仿真进程，应先按标记 Stop 并核对残留。Test 会实际移动机器人，不用于只读交接。

不要再调用 `.dsh/nav_udp.sh`、`nav_manual.sh`、`nav_simple_bt.sh` 等旧实验脚本；它们保留用于追溯，包含已撤回的 DDS 设置和旧验收口径。

## Ubuntu 手动入口

```bash
source ~/.q2q/step3_env.sh
ros2 launch robot_bringup bringup.launch.py gui:=false world:=q2q_warehouse nav:=true
```

运行诊断 CLI 也先 source 同一份环境。当前环境显式使用默认 Fast DDS、domain 0，撤销 localhost-only 和额外 profile。无需 Cyclone DDS；试验下载的包未安装进系统，也未成为当前依赖。

VM 当前为 4 vCPU、约 12.5 GiB 内存。曾在 16 vCPU / Hyper-V 兼容后端下观测到严重调度延迟；降核后性能改善。这是本机实测配置，不是所有 VM 的通用推荐。修改前的 `.vbox` 配置存于 `.dsh/runs/2026-10-22-step3/before_cpu_change.vbox`；如需回到 16 核，应先正常关机再修改。

## 反馈与接口

| 接口 | 来源与用途 |
|---|---|
| `/a200_0000/ground_truth/odom` | Gazebo 原生 OdometryPublisher 的物理位姿/速度；用于当前导航及停稳验收 |
| `/a200_0000/platform/odom` | 轮编码器积分估计；保留作打滑对照，不能代替真实车体位移 |
| `/a200_0000/tf` | `odom→base_footprint` 仅由物理真值桥发布；关掉差速器/EKF 对该段的重复发布 |
| `/a200_0000/tf_static` | 当前定位提供 `map→odom` 恒等变换；机器人固定坐标仍由 RSP 发布 |
| `/a200_0000/sensors/lidar2d_0/scan` | 轴对齐静态 box 的二维理想射线；不含噪声、反射率或动态物体 |
| `/a200_0000/navigate_to_pose` | 标准 `nav2_msgs/action/NavigateToPose` |
| `/a200_0000/cmd_vel` | Nav2/velocity_smoother → twist_mux → 差速控制器；实际运动仍由物理引擎执行 |

真值里程计是观测接口，不传送/瞬移机器人。Nav2 仍通过速度控制器驱动车轮，接受碰撞和接触约束。当前轮胎摩擦方向和打滑系数属于仿真基线参数，未作实机标定。

## 验收口径

- A：`(3.0, -2.5, 0.0)`；B：`(-3.5, 2.0, 3.14)`。各自必须返回 SUCCEEDED。
- map 位姿和物理真值位姿均检查：位置误差 ≤0.25 m、朝向误差 ≤0.25 rad；控制器内部目标容差为 0.15 m/rad。
- 到位与取消后都要有新鲜物理里程计：线速度 <0.02 m/s、角速度 <0.05 rad/s，持续 ≥0.5 仿真秒；失联/旧零速不能算停稳。
- 取消测试在向 `(3.5,4.0,0.0)` 导航 8 秒后发出；必须观测到实际运动、取消被接受、终态为 CANCELED；取消至停稳验证预算 3 秒墙钟。
- 停止后重新启动再测，确认不存在残留 Gazebo/同名节点。轨迹另外按完整轮胎外缘轮廓检查静态障碍重叠；这是二维几何审计，不替代三维接触评测。

轨迹中每行依次是 `sim_s, map_x, map_y, map_yaw, physical_x, physical_y, physical_yaw`。

## 地图和资产维护

当前地图是 `robot_worlds/maps/q2q_warehouse_ground_truth.{pgm,yaml}`；历史 SLAM 地图保留为 `q2q_warehouse.{pgm,yaml}`，不能混称来源。

```powershell
python q2q_harness\sim\robot_worlds\scripts\generate_map.py
pwsh -File .dsh\step3.ps1 -Action Deploy
```

地图与二维激光都会把全部 box 投影成导航障碍，包括矮料箱；这是一致的理想二维导航世界，不是实际激光高度截面。地图生成器对旋转模型、局部偏移或非 box 几何会拒绝处理，扩展场景时需同步扩展生成器和激光模型。

当前仓库 `bin_2` 已从 `(0.4,0.6)` 移到 `(0.4,1.2)`，为出生点留出整车转向空间。完整轮胎外缘轮廓约 `0.9874×0.6693 m`，不是仅用车体内切圆。
