## 1. 一句话

一台差速底盘（Jackal J100）装六轴臂（Kinova Gen3 Lite + 2F Lite），在 Gazebo Fortress 里
**用一条 START 命令**完成「导航到工位 → 真值对接 → 锁底盘 → 抓取 → 收臂 → 出站 →
运回投放点 → 放货 → DONE」，全程 12 个状态、10 Hz 状态记录、关键动作带物理判据。

## 2. 12 状态链（一次任务）

```text
IDLE → NAV_TO_PICK → WAIT_STILL → DOCKING → PICK_READY → PICKING
     → PICKED → STOWING → UNDOCKING → NAV_TO_PLACE → PLACE_READY → DONE
```

| 段 | 判据（来自物理真值，不看「看起来动了」） | 证据话题/文件 |
|---|---|---|
| 导航 + 对接 | 停在 x=0.876 m（窗口 0.86–0.90），横向与偏航在窗内 | `/a200_0000/ground_truth/odom` |
| 抓取 | 抓取流水线自带 P1–P6 门禁 + 动作终态 | `grasp_action_*.json` |
| 收臂 | JTC 终态与关节到位 | `orch.log` / `rec.log` |
| 出站 | 先退到 x≤0.64 且停稳，才允许 Nav2 接管回程 | 状态转移 `UNDOCKING → NAV_TO_PLACE` |
| 投放 | 独立落地门禁：相对车前方 0.40 m 的 xy 误差 <80 mm、中心 z 15–40 mm、连续 3 帧位移 <5 mm | `pose/info` 真值 |
| 全程 | `late_events=0`、锁按阶段正确翻转、10 Hz 记录不断 | `~/.q2q/records/<episode>/task_state.jsonl` |

## 4. 一条反例（证明门禁是真门禁）

`step7_1024_195922`：状态机走到 **DONE**，但独立落地门禁判 **失败**——投放代码漏了四元数
`w=0`，MoveIt 把非法 `(0,1,0,1)` 换成了单位姿态，箱子没落到车外。
修掉 `w=0` 并加 ROS 消息回归测试后才通过。
**所以：DONE 只是状态机的结论，落地以独立门禁为准。** 这个反例保留在
`artifacts/.../failed_delivery/`。

## 5. 不证明什么（答辩时主动说，别被问出来）

1. **不是物理夹持**：物体由 `kinematic_carry` 插件按末端位姿 `set_pose` 带走，
   不是夹持力、也不是真空吸附；摩擦抓取 P7 仍不成立。
2. **不是泛化可靠性**：3/3 是同一个固定场景、同一组参数，不能写成成功率。
3. **不是全故障注入**：正常链是实跑；取消/失联只有离线事件表（23 条）与 PICKING 记录回放。
4. **不是连续订单**：投放后没有自动收臂/复位，第二单要先 Stop/Start 回基线。
5. **不是完整 VLM/Harness**：`Subgoal`、Q2Q-VLM、Km-Transformer 尚未实现；
   当前通过的是「中层串行调度 + 低层仿真执行」。

## 6. 答辩演示（三条命令）

```powershell
Set-Location 'E:\毕设'
& .\.dsh\demo.ps1            # 一键：起栈 + 挂 Gazebo 窗口 + RViz + 跑整链 + 自动截关键帧
& .\.dsh\step3.ps1 -Action Stop
```

自动截图落在 `docs/evaluations/artifacts/<日期>/demo-<时刻>/`，文件名就是状态名
（`02_PICKING.png` … `07_DONE.png`），答辩时可直接按顺序讲。

演示结构是 **headless 栈 + 独立 GUI 客户端**（`ign gazebo -g --render-engine ogre`）：
渲染崩了、关窗、重开都不影响正在跑的任务。**不要**用单进程 `gui:=true` 跑演示
（会把渲染和控制器挤在一个进程，冷启动时 `controller_manager` 可能被拖死）。
RViz 需要 `XAUTHORITY`；Gazebo 需要 `--render-engine ogre`（默认 ogre2 在 SVGA3D 上视口空白）。
