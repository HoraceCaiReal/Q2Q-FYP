# 2026-10-20 第 3 步（Nav2 导航链路）方案裁决

> 结论先行：TF 走 **方案 A**（不动 `robot.yaml`，Nav2 搬进 `a200_0000` 命名空间）；
> 世界自建（静态 box 拼货架料箱）、地图用 `slam_toolbox` 真扫。
> 本文只记「为什么这么定」和「定完之后的约束」；具体接口字段在步骤 2.2 逐条敲定后补。

## 0. 背景：两件被混淆的事

| | 根化补丁（第 2 步已完成） | TF 命名空间（第 3 步要定） |
|---|---|---|
| 改什么 | TF 树的父子关系（谁是谁的父） | TF 消息发到哪个话题（地址） |
| 动作 | `base_footprint_joint` 的 parent/child 对调，偏移 +0.132 → −0.132 | 无（本次裁决为「不动」） |
| 现状 | 根 = `base_footprint`，34 link 无断裂，已验收 | `/a200_0000/tf`；frame 名不带前缀 |

一句话：根化补丁决定**树长什么样**，命名空间决定**消息发到哪个地址**。

## 1. TF / 命名空间：方案 A

**实测依据**（VM 里的真实文件）：

- `clearpath_platform_description/launch/description.launch.py`：RSP 写的是
  `remappings=[('/tf', 'tf'), ('/tf_static', 'tf_static'), ('joint_states', 'platform/joint_states')]`
  —— **全是相对名**；
- `clearpath_common/launch/platform.launch.py`：整组被 `PushRosNamespace(namespace)` 包住，`namespace = a200_0000`；
- 两者相乘 → TF 落在 `/a200_0000/tf`，而 frame 名保持 `base_footprint` / `odom` / `map`。

**裁决**：不动机器人，把 Nav2 搬进同一个命名空间。

- 做法：`nav2.launch.py` 里 `GroupAction([PushRosNamespace('a200_0000'), IncludeLaunchDescription(nav2_bringup/bringup_launch.py, launch_arguments={'use_namespace': 'true', 'namespace': 'a200_0000', ...})])`
- 效果：Nav2 内部所有相对名（`tf` / `cmd_vel` / `odom` / `scan`）自动变成 `/a200_0000/*`，
  和 RSP、激光桥、`diff_drive`、`twist_mux` **零 remap 对上**。

**拒绝方案 B**（`robot.yaml` 里 namespace 改空、全栈回根）：命令虽短，但要重跑第 1/2 步全套验收，
且与 Clearpath 生成器、`control.yaml`、`twist_mux.yaml` 的「相对名 + 命名空间」设计拧着走。

**定完之后的约束**：

1. 验收命令带前缀：`ros2 action send_goal /a200_0000/navigate_to_pose ...`
2. RViz 必须显式 remap（rviz 的 TF 显示用绝对名）：
   `-r /tf:=/a200_0000/tf -r /tf_static:=/a200_0000/tf_static`
3. Nav2 参数文件**顶层键写 `a200_0000:`**，因为 `navigation_launch.py` 用 `RewrittenYaml(root_key=namespace)` 读参数；
   写法与 `control.yaml`、`twist_mux.yaml` 保持一致。

## 2. cmd_vel：零新增节点

实测链路（全部来自 VM 现有文件，不是推测）：

```
controller_server --/a200_0000/cmd_vel_nav--> velocity_smoother --/a200_0000/cmd_vel--> twist_mux
twist_mux --/a200_0000/platform/cmd_vel_unstamped--> platform_velocity_controller(diff_drive) --> 4 轮
```

- `nav2_bringup/launch/navigation_launch.py` 第 122/205 行：controller_server 的 `cmd_vel` remap 成 `cmd_vel_nav`；
  第 183/242 行：velocity_smoother 的 `cmd_vel_smoothed` remap 成 `cmd_vel`。
- `~/.q2q/setup/a200_kinova/platform/config/twist_mux.yaml`：`topics.external.topic: 'cmd_vel'`，priority 1，timeout 0.5 s。
- `clearpath_control/launch/teleop_base.launch.py`：`remappings={('cmd_vel_out', 'platform/cmd_vel_unstamped')}`。
- `platform/config/control.yaml`：`use_stamped_vel: False`（订的是 `Twist` 不是 `TwistStamped`）。

**结论：不写转发节点、不加 remap。** 参数文件里只写两条相对 topic 路径：
`scan.topic: sensors/lidar2d_0/scan`、`odom_topic: platform/odom`。

## 3. 世界与地图

**资产盘点（实测）**：

- `/usr/share/gazebo-11/models` 不存在；`~/.gz/fuel` 为空 → 本地**没有任何**货架 / 料箱模型。
- Clearpath 自带 `clearpath_gz/worlds/warehouse.sdf`（271 行）可用，但嵌了 **27 个 Fuel 在线模型**
  （`shelf` / `shelf_big` / `pallet_box_mobile` / `Warehouse`），首次启动要联网下载、且换机器结果不一定一致。
- `fuel.gazebosim.org` 可达（HTTP 200）→ 留作「要好看截图」时的备选，**不做基线**。

**裁决**：

1. 新建 `robot_worlds/worlds/q2q_warehouse.sdf`：静态 `box` 拼 4 组货架 + 4 个料箱 + 三面墙，
   尺寸全部外置到参数（第 8 步「改场景不改代码」直接满足）。
2. 地图用 `slam_toolbox`（已装）真扫一张，存 `robot_worlds/maps/q2q_warehouse.{pgm,yaml}`，之后 `map_server` + AMCL 使用。

**为什么够用**：2D 激光只看平面截面，`box` 与精细货架在代价地图上等价；
要视觉保真时只换世界文件，导航/规划代码一行不动。

## 4. 四条接口（2026-10-21 已敲定，用户同意）

| # | 接口 | 类型 | 敲定值 | 为什么必须先定 |
|---|---|---|---|---|
| 1 | 激光观测源 | param（costmap 配置） | topic 写**相对名** `sensors/lidar2d_0/scan`；local 用 `voxel_layer`，global 用 `obstacle_layer`；`raytrace_max_range` 3.0 m、`obstacle_max_range` 2.5 m；频率 15 Hz | 写错代价地图就是空的，车会直接撞货架，而规划器还以为路是通的 |
| 2 | 地图文件 | param（`map_server` 的 `yaml_filename`） | `robot_worlds/maps/q2q_warehouse.{pgm,yaml}`；`resolution` 0.05；`origin` 由建图产出决定，不手填 | 没图就没有 `map` 帧，AMCL 发不了 `map→odom`，整条导航链起不来 |
| 3 | `navigate_to_pose` | action（`nav2_msgs/action/NavigateToPose`） | goal 容差 xy 0.25 m、yaw 0.25 rad；取消 = 立即停（速度归零） | 验收命令就是它，容差直接决定「算不算到了」 |
| 4 | 底盘停稳判据 | topic（`nav_msgs/msg/Odometry`）+ param | 线速度 < 0.02 m/s **且** 角速度 < 0.05 rad/s，**持续 0.5 s** | 第 7 步「停稳再动臂」靠它，现在定好以后直接复用 |

> 定完这四条，`项目节点总览.md` **仍然不动**：那里面记的是「已接上」，要等代码写完、验收通过才改状态。
