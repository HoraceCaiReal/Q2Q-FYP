# 第 7 步附加片：吸附式夹持（明确标注为「真空吸近似」）

> **历史方案，已被第四轮实现覆盖，不是当前部署说明。** 下文DetachableJoint、“P5/P6必然通过”等属于当时设想，未由此证明。当前实现是显式运动学支撑插件，不是物理吸附；ROS仍沿用`suction_approx`字段。接口、证据与剩余事项以[最新验收](../evaluations/2026-10-24-第7步整链修复与验收.md)和[交接包](../../archive/2026-10-24-第7步交接/README.md)为准，不执行本页旧命令。

> 用户预授权：「夹持实在不行我们就得动用相近的成熟方案」「实在不行我们再走吸盘」。
> 摩擦抓取的最后一次尝试（见 `logs/2026-10-24.md`「最后一次尝试」）未能被公平检验：
> 50 mm 的物理证据稳定（指尖间距 59.6–60.5 mm、箱子只被推 0.6–6.5 mm），
> 但卡在 JTC 终态语义、关节状态字段与墙钟预算四处相互牵连的问题上。
> 因此转用 Gazebo 自带的**吸附式**机制，把「抓取」这一段真正闭环。

## 0. 这是什么、不是什么（最重要的一节）

**是**：Gazebo `DetachableJoint` 系统——对应真实工业里的**真空吸盘**：接触后把物体与末端刚性连接，
松爪时断开。这是 Gazebo 生态里的标准做法，不是编造数据。

**不是**：**不是** 2F Lite 的摩擦夹持。指面与箱子之间的摩擦、夹持力、指面几何这一段**没有被验证**。
所以：

- 每次抓取的 JSON 必须写 `grasp_mode = "suction_approx"`；
- 文档、日志、答辩口径一律写「吸附近似」，**不得**写「夹爪抓取成功」；
- 第 6 步的 P5/P6/P6b 在这种模式下**必然通过**（物体是刚性连接的），
  因此它证明的是**流程与坐标链**，不是夹持力学。

## 1. 接口五问

### I15 吸附指令（ROS 侧）

| 问题 | 定稿 |
|---|---|
| 解决什么 | 让上层用一条 ROS 消息决定「吸住 / 松开」，而不是直接操作仿真 transport |
| 通信类型 | `topic` |
| 对象类型 | `std_msgs/msg/Bool` |
| 谁发谁收 | `grasp_io`（抓取流水线）/ `orchestration_node`（投放）→ `suction_relay`，话题 `/q2q/low/suction` |
| 频率/QoS | 事件驱动（一次性），RELIABLE、KEEP_LAST 1 |
| 失败与超时 | `true`=吸附、`false`=松开；**发出后必须用真值确认**（物体是否跟手/是否落回），不允许只信消息 |

### I16 仿真侧（实现细节，不是 ROS 接口）

`DetachableJoint` 插件挂在**机器人模型**上：

```xml
<plugin filename="libignition-gazebo6-detachable-joint-system.so"
        name="ignition::gazebo::systems::DetachableJoint">
  <parent_link>arm_0_gripper_left_finger_dist_link</parent_link>
  <child_model>pick_bin</child_model>
  <child_link>link</child_link>
  <attach_topic>/q2q/suction/attach</attach_topic>
  <detach_topic>/q2q/suction/detach</detach_topic>
  <suppress_child_warning>true</suppress_child_warning>
</plugin>
```

`suction_relay` 收到 ROS `Bool` 后，用 `ign topic pub ... ignition.msgs.Empty` 打到上面两个 topic。
（已确认 6.18 的插件支持 `attach_topic`/`detach_topic`：`strings` 里两项都在。）

## 2. 流程里的落点

| 阶段 | 动作 | 判据 |
|---|---|---|
| 合爪后 | 发 `true`（吸附） | 之后第一次抬升必须看到物体 z 跟随 |
| 抬升 | 不变（3 步 ×25 mm） | P6 |
| 静置 | 不变（15 s） | P6b |
| 投放 | 发 `false`（松开）→ 再张开夹爪 | 物体落回台面（真值 z 下降） |

**失败/取消**：任何异常路径都必须发一次 `false`，不允许把物体「挂」在手上退出。

## 3. 验收（这一片怎么算通过）

1. 吸附后 3 步抬升物体跟随 ≥50 mm，静置 15 s 不掉（P5/P6/P6b）；
2. 投放时 `false` 之后物体与夹爪脱离（真值显示物体 z 下降/与末端距离增大）；
3. 每次 JSON 带 `grasp_mode=suction_approx`；
4. 取消/异常路径不留吸附（退出后物体不再跟手）。

## 4. 实测结果：**所选机制在本机不工作**（2026-10-24 16:05）

接口与 ROS 侧代码（`suction_relay`、`grasp_run --suction`、编排里 release 先 detach）都已就位，
但**物理侧的挂接机制在本栈里起不来**，两个独立证据：

| 试验 | 做法 | 结果 |
|---|---|---|
| 挂在 URDF 上 | `model_patches.patch_suction_gripper` 把插件写进 `robot.patched.urdf` 的模型级 `<gazebo>` | URDF 里有、生成的 spawn 模型里**没有**（`/world/.../sdf` 查不到 `DetachableJoint`）。原因：机器人是 `ros_gz_sim create` 从 URDF 转 SDF 生成的，**该转换不支持 `<gazebo><plugin>`** |
| 挂在世界文件里 | 把插件挂到 `q2q_warehouse_grasp50.sdf` 的 `pick_bin` 模型上（父/子反过来） | SDF 解析正确（`ign sdf -p` 能看到插件块），但 `ign topic -l` 里**没有** `/q2q/suction/{attach,detach}`，日志一行不打 |
| 隔离最小世界 | 另建 `probe.sdf`：两个 box + 同一插件 | 同样**没有** `/probe/{attach,detach}` topic；`head -12` 日志为空 → 插件在本机 Fortress 6.18 里没有生效 |

**结论**：`libignition-gazebo6-detachable-joint-system.so` 虽然存在、`strings` 里也有
`attach_topic`/`detach_topic`，但在这台 VM 的 Fortress 栈里初始化即静默失败。
**所以「吸附式夹持」在当前仿真栈里不可用**，不是接口问题，是插件运行问题。

### 已经撤掉的无效改动

- 世界文件里的插件块已删除（它不生效，留着只会误导后来者）；
- URDF 侧的 `patch_suction_gripper` 只在 `Q2Q_GRIPPER_MODE=suction` 时写入，且**本文件已注明它进不了 spawn 模型**；
- ROS 侧（`suction_relay`、`/q2q/low/suction`、`grasp_run --suction`）保留——机制一旦可用就能直接用，接口不用再改。

### 剩下三条可行路线（都需要用户定）

1. **自写 gz 系统插件（C++）**：项目里已有能编译的 `robot_sim_control` 包（`gain_system.cpp`），
   在同一工程里加一个「按指令建/断固定关节」的插件。保真度最高，但要写 C++ 并用 gz-sim 的实体/关节 API。
2. **ROS 侧运动学携带**：attach 后每拍把物体的 `set_pose` 设到末端位姿 + 固定偏移。
   需要一条能用的 `set_pose` 通路（gz 服务或 ros_gz 桥）。实现最小，但**这是纯运动学**（不参与物理），标注要求更重。
3. **换渲染/仿真版本**：本机同时装了 `gz-sim8`（Harmonic）的插件，若整栈升到 Harmonic 可能直接可用——
   但这是平台级升级，会牵动第 1–6 步的所有回归，风险最大。
