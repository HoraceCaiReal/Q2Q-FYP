# 第 7 步接口定稿（第一片：只读 WorldState → 状态反馈 → 记录）

> **历史增量设计，不是当前实现清单。** mid/low/record现已有ROS包；TaskState的arm_executing、holding_object仍是false占位，不能从本页设计目标推断已测量。以[节点总览](../../q2q_harness/项目节点总览.md)及[当前交接](../operations/当前开发交接.md)为准。

> 依据：教程 13 章「任务调度与互锁」的建议落地顺序，以及 10-24 交接里
> 「top/mid/low/record 四层仍未实现」。本文件只定接口，不写实现。
> 每一行都按铁律 7 落到 ROS2 四类之一（topic / service / action / param）。

## 0. 这一片做什么、不做什么

**做**：把「底盘是否新鲜/是否停稳、机械臂是否收拢/是否在执行」这四个条件
**按 10 Hz 测出来、带身份发出去、落盘记录**。全程**只读**，不发布任何运动命令。

**不做**（留给后面几片）：状态转移的实际驱动、导航 action 的调用、`base_command_locked` 的真实加锁、
持物判定、恢复与重规划。这一片结束时，`state` 恒为 `IDLE`，`blocked_by` 会明说缺哪一条。

## 1. 两个节点

| 节点 | 所在层 | 职责 | 输入 | 输出 |
|---|---|---|---|---|
| `worldstate_node` | `mid/` | 订阅真值 odom + joint_states，评估四条不变量条件，10 Hz 发布 `TaskState` | 2 个 topic | 1 个 topic |
| `state_recorder` | `record/` | 订阅 `TaskState`，每条写一行 JSONL | 1 个 topic | 1 个文件 |

两个节点都不发送运动命令；`grep` 验证：不含 `cmd_vel`、`joint_trajectory`、`navigate_to_pose` 的发布者。

## 2. 新消息：`q2q_interfaces/msg/TaskState`

```text
# 第 7 步：任务-世界状态的单一事实来源（本片只读）
std_msgs/Header header        # stamp = 采样时刻；frame_id = "map"

# 身份：迟到结果必须能被识别，所以每次转移都要能追溯
string episode_id             # 本次运行编号
string task_id                # 一条取放任务的 id
uint32 generation             # 阶段代数，每次状态转移 +1

string state                  # IDLE/NAV_TO_PICK/WAIT_STILL/PICK/STOW/NAV_TO_PLACE/PLACE/DONE/CANCELING/FAILED

# 不变量所需的四个条件（UNKNOWN 一律按“不满足”处理）
bool base_fresh               # odom 年龄 ≤ freshness_window
bool base_stopped             # 连续 stopped_window 内 |v|≤v_eps 且 |ω|≤w_eps
bool base_command_locked      # 控制权锁定；本片恒 false（尚未实现）
bool arm_stowed               # 机械臂接近收拢位且未在执行
bool arm_executing            # 有未完成的臂动作

# 观测（SI 单位，便于记录与画图）
float64 base_x
float64 base_y
float64 base_yaw
float64 base_speed            # |v|
float64 base_yaw_rate         # ω
bool holding_object           # 本片恒 false（无持物传感器）

# 诊断（给人看，不参与逻辑）
string blocked_by             # 当前缺的条件名；空串表示都满足
```

## 3. 接口五问（逐个敲死）

### I1 底盘真值

| 问题 | 定稿 |
|---|---|
| 解决什么 | 判断「底盘新鲜 + 停稳」——这是 `arm_execute` 的前置条件 |
| 通信类型 | `topic` |
| 对象类型 | `nav_msgs/msg/Odometry` |
| 谁发谁收 | Gazebo 真值桥 → `worldstate_node`，话题 `/a200_0000/ground_truth/odom` |
| 频率/QoS | 25 Hz，RELIABLE、KEEP_LAST 10 |
| 失败与超时 | 年龄 > `freshness_window`（默认 0.3 s）→ `base_fresh=false`，`blocked_by="stale_odom"`；**不推进状态** |

### I2 关节状态

| 问题 | 定稿 |
|---|---|
| 解决什么 | 判断「机械臂收拢 + 无未完成动作」——这是 `base_navigate` 的前置条件 |
| 通信类型 | `topic` |
| 对象类型 | `sensor_msgs/msg/JointState` |
| 谁发谁收 | 仿真 → `worldstate_node`，话题 `/a200_0000/platform/joint_states` |
| 频率/QoS | ~50 Hz，RELIABLE、KEEP_LAST 10 |
| 失败与超时 | 超过 0.5 s 无消息 → `arm_stowed=false`（UNKNOWN 不当作安全） |
| 收拢判据 | 六个 `arm_0_joint_*` 与零位差 ≤ 0.25 rad（参数可调）；`arm_executing` 本片恒 false（无执行器接口可查） |

### I3 状态发布

| 问题 | 定稿 |
|---|---|
| 解决什么 | 给上层/记录/后续互锁一个统一的、带身份的状态源 |
| 通信类型 | `topic` |
| 对象类型 | `q2q_interfaces/msg/TaskState` |
| 谁发谁收 | `worldstate_node` → `state_recorder`、以及后续的调度/记录消费者，话题 `/q2q/mid/task_state` |
| 频率/QoS | 10 Hz（`publish_rate` 参数），RELIABLE、KEEP_LAST 1 |
| 失败与超时 | 无订阅者不影响发布；发布不因落盘失败而阻塞 |

### I4 记录落盘

| 问题 | 定稿 |
|---|---|
| 解决什么 | 事后复盘/评测要有原始数据，且迟到事件不能无迹可查 |
| 通信类型 | **文件**（不是 ROS 接口；节点对外的接口只有 I3 的订阅） |
| 对象类型 | JSONL，一行一条 `TaskState` |
| 谁发谁收 | `state_recorder` → `~/.q2q/records/<episode_id>/task_state.jsonl` |
| 频率/QoS | 每条样本一行；`fsync` 每次写 |
| 失败与超时 | 打不开/写失败 → 打印 FATAL 并退出（**不允许静默丢记录**） |

### I5 参数

| 问题 | 定稿 |
|---|---|
| 通信类型 | `param` |
| 参数 | `episode_id`、`freshness_window`(0.3)、`stopped_window`(0.5)、`v_eps`(0.01)、`w_eps`(0.02)、`publish_rate`(10.0)、`stowed_deg`(14.3≈0.25 rad)、`record_root` |
| 校验 | 全部 `declare_parameter` + 默认值 + 范围校验；越界**启动即失败**（`episode_id` 为空也失败） |

## 4. 不变量怎么在这一片体现

章 13 要求不变量是可核对的。本片只**测量并发布**，不执行：

| 不变量 | 本片行为 |
|---|---|
| `arm_execute ⇒ base_fresh AND base_stopped AND base_command_locked` | 前两条如实测量；`base_command_locked` 恒 false → 唯一能得出的结论是「**现在不允许动臂**」，这正是本片要证明的（13-A 的答案） |
| `base_navigate ⇒ arm_stowed AND NOT arm_executing` | `arm_stowed` 如实测量；`arm_executing` 恒 false 并标注「未知按不安全处理另见 slice 2」 |

## 5. 验收（这一片怎么算通过）

1. 4 个控制器 active 时启动，`/q2q/mid/task_state` 以 10 Hz 出数，字段齐全。
2. 手动让底盘动 4 s：`base_stopped` 变 false，停稳 0.5 s 后变 true；`state` 恒 `IDLE`。
3. 把真值桥停掉（或暂停仿真）：`freshness_window` 内 `base_fresh=false`、`blocked_by="stale_odom"`。
4. `state_recorder` 产出 JSONL：行数 ≈ 10 × 时长（±10%），stamp 单调递增，可被脚本解析。
5. `grep` 证明两个节点都不发布运动命令。
6. 全部验收命令与输出写进当日日志。

**已知边界（写进代码注释与本节）**：

1. 节点带 `use_sim_time:=true`，定时器由 `/clock` 驱动。**仿真暂停/崩溃时节点停止发布**，
   下游必须用「消息年龄」判断，不能只看最后一条。slice 2 的互锁消费者要按这条实现。
2. `arm_stowed` 在机械臂未收拢时正确为 false（本轮现场臂停在抓取位，实测 `arm_stowed=false`）。
3. `holding_object`、`arm_executing`、`base_command_locked` 三个字段本片恒 false，是**占位而非测量**。
