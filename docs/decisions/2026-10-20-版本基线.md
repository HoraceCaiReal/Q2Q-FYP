### 两条必须记住的版本坑

1. **VM 里同时装了 Harmonic（gz-sim 8.15.0）和 Fortress（gz-sim 6.18.0）**。
   Ros 侧 `ros_gz 0.244` 对应 **gz-sim6**，`ros2 launch` 走 `ign gazebo --force-version 6`。
   谁要是直接敲 `gz sim xxx.sdf`（= `gz sim8`），得到的是 Harmonic，会和 ros_gz 对不上。
   → 一律通过 `ros2 launch robot_bringup bringup.launch.py` 启动，不要手敲 `gz sim`。
   → 第 1 步已确认：`ignition-fortress` 与 `gz-harmonic` 共存，不影响 Clearpath 启动。
2. **`ros_gz_sim` 的 `gz_version` 默认就是 6**，不要传 8。

## 2. 工作空间与包划分

Windows `E:\毕设` 是唯一源，1:1 镜像 VM `~/ros2_ws/src`；`.dsh/sync.ps1` 负责推送 + colcon 构建。

```
E:\毕设\q2q_harness\sim\          ← ROS2 包（第 1 步建的）
  robot_bringup\                  统一启动入口 + 参数 YAML
  robot_worlds\                   Gazebo 世界（纯数据）
E:\毕设\q2q_harness\{top,mid,low,record}\   ← Q2Q 五层，仍是空的（后续步骤）
```

按「一个包只干一件事」拆，后面按步骤补：

| 包 | 何时建 | 职责 |

## 3. 定下的三条约（后面所有步骤都要遵守）

1. **参数外置**：可调参数只写 `robot_bringup/config/bringup.yaml`；机器人本体只写
   `robot_bringup/config/robot.yaml`；launch 里不许出现魔法数字。
2. **命名空间与帧命名**：
   - 节点/话题在命名空间 `a200_0000` 下（`/a200_0000/platform/odom`、`/a200_0000/cmd_vel`…）。
   - TF frame **不带**命名空间：`odom → base_link → {wheel_*, lidar2d_0_laser, arm_0_base_link → … → arm_0_end_effector_link → arm_0_gripper_*}`。
   - **陷阱**：Clearpath 把 `/tf` 也放进命名空间了（发布在 `/a200_0000/tf`）。在根命名空间调试要 remap：
     `ros2 run tf2_ros tf2_echo odom base_link --ros-args -r /tf:=/a200_0000/tf -r /tf_static:=/a200_0000/tf_static`。
     第 3、4 步接 Nav2/MoveIt 时必须统一决定：要么它们也进 `a200_0000` 命名空间，要么把 tf 桥回全局。
3. **世界文件命名**：文件名 == `<world name>`，且不引 Fuel 远程模型（`warehouse.sdf` 首次启动要下模型，曾把 VM 拖死）。

## 4. 第 1 步验收结果（2026-10-20 实测）

命令：`ros2 launch robot_bringup bringup.launch.py gui:=false`

| 验收点 | 结果 |
|---|---|
| 仿真起来 | ✅ `/clock` 在走，`ign model --list` = `ground_plane` + `a200_0000/robot` |
| `ros2 node list` | ✅ 18 个节点 |
| `ros2 topic list` | ✅ 30 个话题 |
| 控制器 | ✅ `arm_0_joint_trajectory_controller` / `arm_0_gripper_controller` / `joint_state_broadcaster` / `platform_velocity_controller` 全 **active** |
| 底盘 | ✅ `/a200_0000/platform/odom` @12.5 Hz，`tf2_echo odom base_link` 正常 |
| 机械臂 TF | ✅ `base_link → arm_0_end_effector_link` = (0.057, −0.010, **1.097**) m |
| 激光 | ✅ `/a200_0000/sensors/lidar2d_0/scan` 有真实距离（24.999 m / inf） |
| joint_states | ✅ 含 4 轮 + arm_0_joint_1..6 + 夹爪指 |
| 参数外置 | ✅ 改 `bringup.yaml` 或命令行 `gui:=`/`world:=` 生效 |

**第 1 步顺手修掉的坑（很重要）**：`robot_state_publisher` 之前一直 abort，根因是 `robot.yaml` 里把激光挂到了
`top_plate_mount_d1`——那是 A200 **PACS 板**（`model: pacs`）才有的挂载点，默认板只有
`top_plate_default_mount` / `_front_mount` / `_rear_mount`。URDF 建树失败 → 机器人不 spawn、无 joint_states。
现在改成 `top_plate_front_mount`，`check_urdf` 通过（849 行 URDF，树完整）。
