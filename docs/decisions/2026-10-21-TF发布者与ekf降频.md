# 裁决：TF 发布者只留差速控制器；ekf 降频不再发 TF

- 日期：2026-10-21
- 触发：地图一直糊、`Failed to meet update rate` 常驻、slam 偶发整帧丢激光。
- 结论：`odom→base_footprint` 由 `platform_velocity_controller`（diff_drive）发，
  `ekf_node` 的 `publish_tf: False`、频率 50 → 20 Hz。两条都写进 `model_patches.py` 并在启动时断言。

## 1. 这个 ekf 在本项目里到底在做什么

`~/.q2q/setup/a200_kinova/platform/config/localization.yaml` 全文只有一路输入：

```yaml
odom0: 'platform/odom'
odom0_config: [True, True, False, False, False, True, True, True, False, False, False, True, False, False, False]
frequency: 50.0
publish_tf: True
```

A200 配置里没有 IMU，所以它**不融合任何东西**——只是把 `platform/odom` 在 50 Hz 抄成 TF。
换句话说：它是一条 `odom 话题 → TF` 的转发器，多一个进程、多一次 DDS 往返。

## 2. 它坏在哪（实测）

日志常驻：

```
[ekf_node-7] Failed to meet update rate! Took 0.0400 s. Try decreasing the rate, ...
```

它要 20 ms 一次、实际要 40 ms，于是 TF 的时间戳落后于激光帧。
slam_toolbox 的输入过滤器是 `tf2_ros::MessageFilter`，**队列长度 1**：

```
[slam_toolbox]: Message Filter dropping message: frame 'lidar2d_0_laser' at time 7.740
                for reason 'discarding message because the queue is full'
```

一帧激光只要在到达时查不到对应时刻的 TF，就整帧被丢掉——地图就开始出现「扫过的路径有、墙面缺」的糊图。

## 3. 改法

| 文件 | 键 | 改前 | 改后 | 为什么 |
|---|---|---|---|---|
| `platform/config/control.yaml` | `enable_odom_tf` | `False` | **`True`** | 谁积分轮子谁发 TF，零额外延迟、零额外进程 |
| `platform/config/localization.yaml` | `publish_tf` | `True` | **`False`** | 同一段变换只能有一个发布者 |
| `platform/config/localization.yaml` | `frequency` | `50.0` | **`20.0`** | 它只剩「给别的节点看位姿」的用途，20 Hz 够，CPU 省一半 |

为什么「同一段变换只能有一个发布者」：TF 是「谁后到听谁的」，两个源都以不同节拍发布同一段
`odom→base_footprint`，下游看到的变换时间戳会来回跳，slam 的扫描匹配会被这种抖动带偏。

## 4. 验收（改完之后）

| 检查 | 结果 |
|---|---|
| `Failed to meet update rate` | 从「一直刷」变成 **0 次** |
| `odom→base_footprint` 的发布者 | `platform_velocity_controller` |
| `enable_odom_tf` / `publish_tf` / `frequency` | `True` / `False` / `20.0`（`verify()` 每次启动断言） |

补丁是幂等的：`_replace_flag` / `_replace_scalar` 命中数不等于 1 就直接中止启动，
不会出现「补丁没打上但照常跑」。

## 5. 顺带说明：这一步**没有**解决地图的另一个问题

改完 ekf，地图依然一个障碍格都没有。真正的病根是激光拿不到回波（见
`docs/decisions/2026-10-21-激光改用几何射线.md`）：
720 束里只有 8 束有值，且值全等于 24.999（= `range_max`，即「什么都没打到」）。
两件事互相独立，先后顺序是：先让 TF 不丢帧（本文件），再让激光有数据（下一份）。
