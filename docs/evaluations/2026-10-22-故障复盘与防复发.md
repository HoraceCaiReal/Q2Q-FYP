# 第 3 步故障复盘与防复发

日期：2026-10-22。依据：10-16 至 10-22 日志、修复前只读取证、当前源码、两轮独立启动验收及实时演示 JSON。区分观察与归因，用于开发交接及论文过程回顾。执行命令见 [运行说明](../operations/第3步导航运行.md)。

## 为何会长时间卡住

真实渲染限制、虚拟化调度延迟、参数/命名空间集成错误、相互矛盾的实验脚本、残留进程与缺乏物理真值的验收同时存在。没有先固定运行条件与验收器，持续叠加环境、行为树和超时修改，导致后续现象难以归因。没有证据需要重写 Nav2 或抛弃机器人资产。

恢复顺序：固定环境/入口 → 控制器与动作生命周期 → 物理反馈 → 几何/地图一致性 → 两轮独立启动 → 实时渲染。通过是这组修复共同作用的结果，不能宣称每项都完成严格单变量因果实验。

## 逐项问题、修复方针与防复发

### 1. 机器人/机械臂“不出现”（10-16 → 10-20）

- 旧判断：空的 manipulator service 生成文件造成臂未 spawn。后续日志定位到 `robot.yaml` 的 `top_plate_mount_d1` 不属于默认板挂载点，导致 URDF/RSP 失败；改为 `top_plate_front_mount` 后模型、关节和四控制器可用。
- 方针：先看 URDF、RSP 退出码及实体是否 spawn，再分析臂驱动。空生成文件只是线索，不能单独定因。
- 防复发：安装点变动先核对模型/TF。臂可见、控制器 active、执行轨迹、物理抓取是不同关卡；后两项仍待验收。

### 2. 布尔参数、重复命名空间与 YAML 静默失效（10-21）

- 历史已修：`PythonExpression` 收到小写 true/false 并非 Python 布尔；重复 PushRosNamespace 或 `RewrittenYaml(root_key=namespace)` 造成双层命名空间/参数树，出现 `No critics defined`。
- 当前参数 YAML 顶层为节点名，命名空间由 launch 重写；布尔适配对应 launch 的消费方式。
- 防复发：检查**节点实际参数和 launch 生成的最终 YAML**，不只看源文件。topic 地址、frame 名、节点全名、参数树路径分别核对。

### 3. 控制器 already loaded 与副作用调用重试（10-21 → 10-22）

- 原始记录显示服务端已执行 load，客户端超时后重发，第二次才撞 already loaded。不能据此推导 `.type` 会自动重复加载，也不应移除正常类型配置。
- 当前 `ensure_controllers.py` 查询并补齐四控制器状态；成功退出才触发 Nav2，失败拒绝继续。
- 防复发：副作用调用超时后先读状态再决策；只读查询可以有界重试，load/configure/运动动作不能无条件重发。延时可作启动缓冲，不作就绪证据。

### 4. 仿真慢、“83 ms 固定开销”与加核误区（10-20 → 10-22）

- 旧配置测到 RTF 0.07–0.4，推测约 83 ms 固定开销并归到机器人/插件；没有完整剖析，旧数据也不足以支持精确线性模型。
- 新证据：VBox 日志为 NEM/Hyper-V 兼容后端；16→4 vCPU 后，保持 0.02 s 步长，headless RTF 样本为 0.9994、1.0067。存在工程对照，但不能据此宣布唯一底层机制。
- 方针：当前 4 vCPU、12790 MB；未修改 Windows 虚拟化设置。0.02 s 只作为当前导航配置，接触抓取需重新评估。
- 防复发：记录后端、vCPU、负载、步长和 GUI 条件，用 Δsim/Δwall 测 RTF；`/clock` 频率不等于 RTF。更多核、更大步长、更长超时都不自动提高正确性。“0.4 天花板”“不用再查调度”撤回。

### 5. DDS、localhost-only、SHM 与 /tmp 配置污染（10-21 → 10-22）

- 历史有 SHM 错误、失效 profile 路径和不同入口环境不一致；不足以证明默认共享内存永久不可用。UDP-only 被定稿后又撤回，旧清单/脚本却仍启用它。
- 已验收配置：默认 Fast DDS/domain 0；统一 `step3_env.sh`，清 localhost-only、额外 profile、Cyclone URI、IGN_IP/GZ_IP。Cyclone 不是交付依赖。
- 防复发：先比相关进程环境与最小消息/服务往返，再换传输；长期依赖不放 /tmp。不把清理后成功归因为某一个文件，不常规清 `/dev/shm`，尤其不在节点运行时删活动共享内存。

### 6. TF 查错话题/时机与重复发布权（10-20 → 10-22）

- TF 地址为 `/a200_0000/tf`、`/a200_0000/tf_static`，frame 名无前缀。根话题空不等于链断；AMCL 未 active 的 map→odom 缺失要结合定位模式判断。
- 当前真值模式：map→odom 恒等，Gazebo 物理真值桥独占 odom→base_footprint；差速器与 EKF 不重复发该边。
- 防复发：逐边查发布者、时间戳、时钟、重映射与生命周期。TF 总话题有多发布者很正常，冲突取决于**同一条边**。base_footprint 作 URDF 根不是 Nav2 普遍硬要求；当前补丁保留，不能局部随意回滚。
- 更正：单路输入 EKF 仍可能预测/滤波，旧“只是抄一遍、无融合就无价值”过度简化；本次不据此宣称取消 EKF 的普遍必要性。

### 7. 原生激光“有话题就算过”与渲染限制（10-20 → 10-22）

- 曾把 24.999/inf 当作真实回波，后统计仅 8/720 有限且接近 range_max，与近处几何不符；原生激光未有效验收。
- 当前选择理想二维几何激光，RViz 可实时显示模型/数据；Gazebo 原生视口/GPU 激光没有修复。
- 防复发：查新鲜度、距离分布、有限值比例、已知方向/几何与移动后的变化。“≥500 束”只可能是固定场景的辅助条件，不是所有姿态的通用门槛。
- 边界：Accelerated:no、空白视口和异常 scan 支持当前后端路径有问题，不证明所有相机/渲染永不可用。GL 能初始化也不保证深度正确；原生传感器回归独立排期，不占 demo 关键路径。

### 8. SLAM 来源、地图地址与理想激光假设（10-21 → 10-22）

- 历史 SLAM 命名空间、绝对 `/map`、TF 重映射不一致；有文件不代表地图质量过关，零障碍地图不能证明建图成功。
- 当前验收地图为 SDF 生成的 `q2q_warehouse_ground_truth.{pgm,yaml}`；旧 `q2q_warehouse.{pgm,yaml}` 保留历史，不混称当前 SLAM/AMCL 已通过。
- 理想激光投影所有静态 box，包括低于激光高度的箱子，无噪声/动态物体/自遮挡；真值定位让查询与 world 对齐。平行 slab 漏判已修，scan_time 与配置速率一致。
- 防复发：改模型同时查 SDF、地图、激光、出生点、footprint；生成器拒绝不支持的几何，激光支持范围单独核对，不能默认两者同样严格。AMCL 回归须独立评估定位误差/漂移，同源真值输入不能证明定位能力。

### 9. 把恢复树末尾报错当最初根因（10-22）

- 时间线显示 FollowPath 已收，BT 等确认超时返回 FAILURE；controller 后来仍 reached，之后才有恢复抢占错误。去掉恢复节点不足以解释全部问题。
- 当前最小重规划+跟踪 BT `navigate_w_replanning_time.xml`，确认 2000 ms、循环 100 ms、服务就绪 10000 ms，RPP 5 Hz；保留心跳，预算 30 s。
- 防复发：分别记 request/accepted/result/cancel/物理停止，区分 ms/s、仿真/墙钟。某次 configure 约 6.5 分钟没有逐库计时，不能说全因 dlopen 或定为正常启动预算。
- 未解决：完整恢复树、DWB 对照未验收。最小 BT 是当前范围，不等于恢复行为已修好。

### 10. 轮式 odom 显示到了，物理车体未必到了（10-22）

- 发现轮积分与实际运动严重不一致，打滑时轮子转不代表车体位移；旧 0.233 m 不能证明真实到位。
- 接 Gazebo 原生 OdometryPublisher；验 map/物理误差与速度，以原生实体查询交叉核对；修摩擦方向、WheelSlip 参数和轮距补偿。这些是本仿真工程参数，未作实机标定。
- 防复发：结果明确反馈源；截图、规划路径、编码器、action 成功各自证明不同事实。真值模式 map 与物理值共享来源，不是独立定位评测；原生查询是实现交叉检查。

### 11. 取消与停稳验收可能假通过（10-22）

- 旧客户端混 map 目标与 odom，漏 yaw；默认 speed=0 可把没数据判停稳；丢 cancel future，漏 CANCELED，超时退出留下任务。
- 新客户端检查新鲜 TF/物理反馈、xy/yaw、实际运动、取消接受和终态、持续低速窗口；超时走取消。未确认终止/停稳都不能算过。
- 防复发：一次一个动作，失败留证后停，不发下一目标。“已发取消”“被接受”“动作终止”“物理停稳”分四状态。未来 executor/watchdog 复用该契约，不凭零 cmd_vel 宣布安全。

### 12. footprint、转向空间与避障证据（10-22）

- 旧内切圆漏车头/尾和轮胎；现矩形 x±0.4937、y±0.33465。bin_2 从 (0.4,0.6) 移 (0.4,1.2)，重生成地图保留出生点转向空间。
- 两轮最终和实时演示的物理轨迹，完整矩形插值二维 box 分离轴审计均 0 重叠；早期旧场景有重叠，不计为最终证据。
- 防复发：存场景版本和轨迹来源，不混报不同场景指标；NavFn 的圆形近似不因配置 polygon 就具备全姿态规划。未来臂外伸须另算整机包络/三维接触。

### 13. 父进程退出但孤儿 Gazebo 仍在（10-20 → 10-22）

- setsid/timeout 或仅追 launch PID 不保证全部派生进程退出，残留会污染资源和动作结果。
- 当前注入唯一 `Q2Q_STEP3_RUN`，按 /proc 标记与 start tick 定向回收；先 SIGINT 后升级，新 Start 拒绝残留 Q2Q Gazebo。
- 防复发：查所有本轮子进程，不能凭父 PID 消失宣布清场，不用旧大范围 pkill。Status 的 running 主要检查父进程，不能单独证明无孤儿，应结合 Stop/Start 和实际进程检查。

### 14. 工具吞退出码与生成补丁重复污染（10-22）

- SSH 后接 echo、构建管道 tail 可能把失败变成功；已透传真实退出码并用 pipefail。修复重复 scan_raw 后缀/真值插件插入风险，连续两次生成核对。
- 防复发：检查退出码与预期产物；补丁应两次运行一致，关键替换断言命中。Windows 是维护源、VM src 是镜像、setup 是生成产物，不只改远端文件。

### 15. 旧架构/已重置代码被当成当前实现（10-19 → 10-22）

- 10-19 的 dry-run/LLM/记录框架随后被用户重置，并更正 harness 与 orchestration 概念；旧测试数、成功率与图不代表当前实现。
- 当前 sim 两包有代码，top/mid/low/record 无实现；orchestration 总调度，harness 只包装 Q2Q-VLM，Km-Transformer 在 VLM 内。
- 防复发：历史标日期/失效原因，入口链接到新证据；先报告实际文件/接口，再谈架构完成度。教学按可理解的最小闭环推进，避免一次堆出学生无法接手的大框。

## 未来排障工作约定

1. 先读 [当前交接](../operations/当前开发交接.md) 和 Status，记环境/场景/参数/反馈源/运行目录；栈已运行不重复 Start。
2. 每次检验一个主要假设，保留基线对照，不拼接旧实验脚本。沿首个异常查真实状态；服务超时不等于未执行，话题存在不等于有效数据。
3. 排查设 20–30 分钟检查点：报告原始证据、已排除项与下个实验，不连续数小时无反馈地同时改多层。
4. 实验记“假设 → 条件/改动 → 命令与退出码 → 原始日志/JSON → 结论强度 → 回退”。失败也存，未证实原因明确写推测。
5. 每次只加一个可验收闭环，先状态/动作适配/记录再扩展调度。Nav2 的 30 s 心跳预算不等于未来安全 watchdog 可接受的停止响应预算。
6. 收工同步日志、交接、运行文档、节点总览；旧决策加更正，保留原证据。实现、推测、暂缓、已撤回分清。

## 未解决项与后续建议
