## 已确认的问题与处理

| 问题 | 证据 | 处理与限制 |
|---|---|---|
| 夹爪第二轮不能张开 | 原样复现 112.3→20.8 mm，下一轮约20.1 mm不动，主关节顶到0.96 | 保留原活动手指；mimic坐标重参数化 + JTC缓慢轨迹 + 0.90软限位 + GripperCommand适配。仅补offset不足以修复 |
| mimic offset 在仿真中无效 | 同版本gz_ros2_control实现只使用multiplier；写参数不等于插件支持 | 将offset烘入关节origin，并同步限位，保持任意主关节角下的FK；三个几何回归测试通过 |
| 动作回报早于物理稳定 | 第一版适配能开合，却在到位前报告stalled | 在位置控制保持期间等待有界稳定时间，再读最新关节位置；不宣称max_effort被执行 |
| 新适配节点自身缺陷 | Node.handle保留属性；Humble多线程wait-set与destroy_timer竞争导致InvalidHandle | 改用jtc_handle；所有等待异步让出，使用单线程executor；未知执行状态锁住新目标 |
| Jackal沿用旧地面高度假设 | raw模型轮心z=.0345、半径.098，旧模型根落地z=.0635 | 新建base_footprint距base_link下方.0635 m；实测模型根z≈-0.000002、末端局部z≈1.12075 m |
| 四元数180°被误读 | protobuf省略w=0，旧实现把0替换为1 | 保留合法w=0；缺整个orientation才用单位旋转；世界转base使用完整平移/旋转 |
| Jackal导航仍用Husky包络 | 两个costmap仍为±.4937×±.33465 m | 改为±.26×±.215 m，覆盖本配置车体/轮子；只适用于机械臂收拢的导航基线 |
| 抓取失败仍继续合爪/抬升 | 原脚本P4超限仅跳出循环，P5/P6只是打印，最后return 0 | P1/P2/P4/P5/P6失败立即中止、非零退出、保存JSON；不再超时盲目重发 |
| 删除目标让规划器看不见碰撞 | 原抓取入口remove_object | 保留目标与桌子，只允许手指与目标接触；预抓取plan_only，执行直接走有界JTC；插入/抬升要求完整笛卡尔路径 |
| 笛卡尔相对jump阈值错误截断 | 同一目标fraction=.03448；取消相对阈值、改绝对.20 rad后fraction=1 | 保留碰撞检查，拒绝部分路径；不能关闭所有安全检查“换成功” |
| 指尖连杆原点被当作指尖实体中心 | 旧下插20 mm后物体移动32.9 mm；STL实体在原点下方仍有长度 | 调整下插目标，让指尖原点在箱心上方15 mm，收紧姿态容差；物理抓取仍需按P5/P6/P7复测 |
| 日常清理使用广泛pkill/删共享内存 | 旧交接给出无进程归属限制命令 | 常规只按Q2Q_STEP3_RUN和PID启动时刻回收；启动后查实际就绪，不固定等100 s |

参考实现：[gz_ros2_control 0.7.21](https://github.com/ros-controls/gz_ros2_control/blob/0.7.21/gz_ros2_control/src/gz_system.cpp)。这是源码支持的接口边界，不把相关性当唯一物理根因。

## 后续接触与启动回归

- 80mm原场景在凸包/5ms对照下仍未取得P6通过，不能把P0已修写成80mm物理抓取已修。
- 50mm、20ms、原mesh对照也出现接触时仿真很慢；增加了堵转后取消闭合斜坡并小量预紧保持的逻辑，但仍按P6判断，不以stalled标志当成功。
- 四个原CAD碰撞网格各13088–17330个三角面。`-GripperCollision convex`在生成目录创建保守凸包与审计，降为1008–1558面；**凸包填平凹槽，会改变碰撞几何**。原CAD/visual/活动关节保留，原mesh仍是默认可选项，未伪装成完全相同的碰撞模型。
- 20ms物理步长原本为导航性能选择。新增50/80接触试验场景使用5ms；原导航世界仍20ms。降低步长、凸包、目标尺寸组成不同试验条件，不能把所有改进归因于单一因素。
- 新接触传感器输出的实际话题为`/world/q2q_warehouse/model/pick_bin/link/link/sensor/pick_contacts/contact`。它给出接触对象/位置，不作为测得夹持力使用。
- 冷启动发现地图服务器配置完成但停在INACTIVE：原lifecycle切换应答超时，导航节点却已ACTIVE。现在导航验收必须收到有效OccupancyGrid；启动guard在地图持续INACTIVE时只按实际状态补一次激活，再用ACTIVE+地图确认结果。保留Nav2原生命周期管理；这个guard不是运行期安全watchdog。
- 空爪客户端原25s等待短于一次真实冷启动。现改为最多90s**等待实际action服务**，不是固定sleep；启动失败与夹爪机械卡住分别记录。
- 新运行器`.dsh/step6.ps1`→`grasp_trial.py`：阶段退出码逐个检查，失败不重发运动；每次独立试验先Stop/Start。世界SDF在启动时快照，并保存SHA256、碰撞profile；抓取JSON保存参数与URDF SHA256。
